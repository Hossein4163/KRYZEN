Approach summary\n\n**Architecture.** Full rewrite from Next.js to **.NET 10 + Clean Architecture** backend plus **React 19 + Vite + Tailwind CSS + Antigravity UI** frontend SPA.\n\nBackend (Clean Architecture, four projects under `src/`):\n- `src/Domain` — entities, value objects, domain events, enums, repository interfaces (no framework dependencies).\n- `src/Application` — use cases (CQRS via MediatR), DTOs, FluentValidation validators, Mapster mappings, service interfaces.\n- `src/Infrastructure` — EF Core 10 `AppDbContext` + Npgsql + PostgreSQL, migrations, seed data, ASP.NET Core Identity, SignalR hubs, Stripe payment adapter, file storage.\n- `src/Api` — ASP.NET Core 10 Web API entry point, controllers/minimal APIs, middleware, OpenAPI/Swagger, `Program.cs`, `appsettings.json`.\n\nFrontend (`frontend/`):\n- React 19 + TypeScript + Vite + Tailwind CSS 4.x + Antigravity UI components styled to Vitrea tokens.\n- `react-i18next` for Persian (fa, RTL default) + English (en, LTR).\n- SignalR JS client for real-time chat.\n- Recharts for charts, `@dnd-kit` for Kanban drag-and-drop, Sileo for toasts, Blobatar for avatar fallback.\n\n**How milestones build on each other.**\n- M1 (solution scaffold + backend infra) creates the .NET 10 Clean Architecture solution, EF Core 10 + PostgreSQL, Identity + JWT, SignalR, Docker Compose, and the React 19 + Vite frontend shell with i18n/RTL. No auth required yet.\n- M2 (auth + roles) adds Identity, JWT bearer auth, role-based policies, login/signup/password-reset endpoints, seed data, and frontend auth pages + route guards. Every later milestone depends on authenticated users with roles.\n- M3 (customer portal) builds on M2: customer dashboard, projects/deliverables, mock checkout, orders/invoices, customer-admin chat.\n- M4 (team area) builds on M2: calendar, Kanban, tasks, reports — team-only routes.\n- M5 (chat) builds on M2 + M3/M4 data models: SignalR `ChatHub`, unread badges, file attachments, customer-admin + team chats.\n- M6 (admin panel) builds on M2 + M3 + M4 + M5: overview dashboard, CRUD over all entities, all-chats view.\n- M7 (Docker + deploy docs) packages everything: backend Dockerfile, frontend Dockerfile, docker-compose (api + postgres + redis), wait-for-db + `ef database update` entrypoint, seed, README, local verification.\n\n**i18n / RTL strategy.** Default locale: Persian (`fa`), RTL. English (`en`) LTR. Locale-based routing on the frontend: `/fa/*` and `/en/*`, with `/fa` as default. `dir=\"rtl\"` on `<html>` for Persian, `dir=\"ltr\"` for English. Persian font: Vazirmatn (self-hosted); English: Inter. All layout, spacing, and text alignment mirror for RTL using logical CSS properties. Sidebar stays on the left for both locales (per Vitrea reference); internal alignment mirrors.\n\n**Auth / RBAC strategy.** ASP.NET Core Identity + JWT Bearer. Roles: ADMIN, TEAM_MEMBER, CUSTOMER. JWT contains role claim; short expiry + refresh tokens. Role enforced via `[Authorize(Policy=...)]` policies + server-side checks in use cases. Admin creates TEAM_MEMBER accounts; customers self-sign up as CUSTOMER.\n\n**Chat strategy.** ASP.NET Core SignalR `ChatHub` pushes new messages to clients; clients send messages via `SendMessage` hub method. JWT auth on hub connection. Unread badges computed from `ReadAt` timestamps per conversation participant. File attachments stored locally (Docker volume) and linked to chat messages.\n\n**SEO strategy.** Public marketing pages are prerendered/server-rendered via Razor Pages or prerendering middleware. Unique title/meta per page/locale, Open Graph tags, JSON-LD (Organization, Service, Offer, BreadcrumbList, Article), `sitemap.xml`, `robots.txt`, semantic HTML, alt text on all images. Lighthouse 90+ target on home page.\n\n---\n\n## 2. RTL rules\n\n1. **`dir` attribute:** `<html dir=\"rtl\" lang=\"fa\">` for Persian (default), `<html dir=\"ltr\" lang=\"en\">` for English. Set in root layout based on active locale; never hardcode `dir=\"ltr\"`.\n2. **Logical CSS properties:** Use `margin-inline-start/end`, `padding-inline-start/end`, `inset-inline-start/end`, `text-align: start/end`, `float: start/end` instead of left/right equivalents. Tailwind logical variants: `ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`.\n3. **Sidebar stays left:** The fixed left sidebar (256px desktop, ~72px collapsed) remains on the left in both `dir=\"rtl\"` and `dir=\"ltr\"` (per Vitrea design decision). Only internal alignment (icon position, text alignment, submenu direction) mirrors.\n4. **Text alignment:** Headings, labels, and body text use `text-align: start` (right in RTL, left in LTR). Numeric data and right-aligned columns in tables use `text-align: end`.\n5. **Mirrors:** Borders that were on the right (e.g., sidebar right border) stay on the right in both locales per Vitrea; padding/margin values mirror via logical properties.\n6. **Typography:** Vazirmatn for Persian script, Inter for English. Font-family chain: `Vazirmatn, Inter, system-ui, sans-serif`. Self-host both with `@font-face` and `font-display: swap`.\n7. **Numbers:** Persian locale uses Arabic-Indic digits (۰-۹) for display; English uses ASCII digits. Dates: Jalali (Shamsi) calendar for `fa`, Gregorian for `en`.\n8. **RTL testing:** Every dashboard page (admin, customer, team) must be visually QA'd in both `dir=\"rtl\"` and `dir=\"ltr\"`; no broken alignment, no overflow, no misplaced icons.\n9. **RTL overrides in Tailwind:** Add `[dir=\"rtl\"]` variants in `tailwind.config.ts` for any component that needs explicit RTL adjustments beyond logical properties.\n\n---\n\n## 8.

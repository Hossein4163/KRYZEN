Product vision\n14\t\n15\tRame Studio is a web design and SEO studio platform that lets customers browse services and packages, place orders, and collaborate with a team through dashboards and real-time chat. Admins manage users, services, packages, orders, invoices, leads, blog, and portfolio. Team members manage their calendar, Kanban tasks, and project work. The platform is bilingual (fa/en, RTL-ready), uses JWT authentication, SignalR chat, and Stripe test-mode payments, built on .NET 10 Clean Architecture backend and React 19 / Vite / Tailwind / Antigravity UI frontend.\n16\t\n17\t---\n18\t\n19\t## 2. User personas\n20\t\n21\t### 2.1 Admin\n22\t\n23\t| Attribute | Detail |\n24\t|-----------|--------|\n25\t| Name | Studio Administrator |\n26\t| Role | `admin` |\n27\t| Goals | Manage the studio business: users, services, packages, orders, invoices, leads, blog, portfolio; oversee team workload; configure platform settings. |\n28\t| Pain points | No central overview of orders and leads; manual user and content management; no visibility into team capacity. |\n29\t| Devices | Desktop (primary), tablet (secondary) |\n30\t| Language | fa / en |\n31\t\n32\t### 2.2 Team member\n33\t\n34\t| Attribute | Detail |\n35\t|-----------|--------|\n36\t| Name | Designer / SEO Specialist / Developer |\n37\t| Role | `team` |\n38\t| Goals | View assigned tasks and calendar, update Kanban task status, chat with customers and admins, log work on projects. |\n39\t| Pain points | Tasks scattered across tools; no shared calendar; slow customer communication. |\n40\t| Devices | Desktop (primary) |\n41\t| Language | fa / en |\n42\t\n43\t### 2.3 Customer\n44\t\n45\t| Attribute | Detail |\n46\t|-----------|--------|\n47\t| Name | Business owner / marketing manager |\n48\t| Role | `customer` |\n49\t| Goals | Browse services and packages, place orders, track project progress, pay invoices, chat with the studio team. |\n50\t| Pain points | Hard to compare service packages; no order status visibility; slow email-only communication. |\n51\t| Devices | Desktop and mobile |\n52\t| Language | fa / en (RTL for Persian) |\n53\t\n54\t---\n55\t\n56\t## 3. Key user journeys per role\n57\t\n58\t### 3.1 Customer journeys\n59\t\n60\t**J-C1 — Browse and select a service package**\n61\t1. Customer lands on the public home page (fa or en).\n62\t2. Browses Services and Packages pages.\n63\t3. Selects a package and views details.\n64\t4. Clicks \"Order\" / \"Get quote\".\n65\t\n66\t**J-C2 — Register and place an order**\n67\t1. Customer signs up (email + password) or logs in.\n68\t2. Completes profile if needed.\n69\t3. Adds a package to cart / submits an order request.\n70\t4. Proceeds to checkout (Stripe test mode in M3, live later).\n71\t5. Receives order confirmation and invoice.\n72\t\n73\t**J-C3 — Track order and chat with the team**\n74\t1. Customer opens the Customer Dashboard.\n75\t2. Views active projects and order status.\n76\t3. Opens Chat to message the studio team (SignalR real-time).\n77\t4. Receives replies and updates.\n78\t\n79\t**J-C4 — Manage account and invoices**\n80\t1. Customer views Orders and Invoices pages.\n81\t2. Downloads invoices, checks payment status.\n82\t3. Updates profile and password.\n83\t\n84\t### 3.2 Team member journeys\n85\t\n86\t**J-T1 — Start the day: calendar and tasks**\n87\t1. Team member logs in to the Team Dashboard.\n88\t2. Views today's calendar events and assigned Kanban cards.\n89\t3. Picks a task and moves it to \"In Progress\".\n90\t\n91\t**J-T2 — Work on a task**\n92\t1. Opens Task Detail from Kanban.\n93\t2. Updates status, adds notes, logs hours.\n94\t3. Moves card to \"Review\" or \"Done\".\n95\t\n96\t**J-T3 — Communicate with customers and admin**\n97\t1. Opens Chat from the Team area.\n98\t2. Replies to customer messages in real time (SignalR).\n99\t3. Escalates issues to admin when needed.\n100\t\n101\t**J-T4 — Report progress**\n102\t1. Views Reports page for personal/team task completion.\n103\t2. Shares status with admin during stand-up.\n104\t\n105\t### 3.3 Admin journeys\n106\t\n107\t**J-A1 — Daily overview**\n108\t1. Admin opens the Admin Dashboard.\n109\t2. Reviews key metrics: orders, leads, revenue, active users.\n110\t3. Checks recent chats and support tickets.\n111\t\n112\t**J-A2 — Manage users and roles**\n113\t1. Opens Users page.\n114\t2. Creates, edits, or deactivates customer/team/admin accounts.\n115\t3. Resets passwords or assigns roles.\n116\t\n117\t**J-A3 — Manage catalog and content**\n118\t1. Creates/edits Services, Packages, Portfolio items, Blog posts.\n119\t2. Publishes or archives content.\n120\t3. Updates pricing and availability.\n121\t\n122\t**J-A4 — Manage orders and invoices**\n123\t1. Opens Orders page; reviews new orders.\n124\t2. Assigns orders to team members.\n125\t3. Generates/sends invoices; tracks payments (Stripe).\n126\t\n127\t**J-A5 — Oversee team and chats**\n128\t1. Views Team calendar and Kanban boards.\n129\t2. Monitors Chats across customer conversations.\n130\t3. Intervenes in customer support when needed.\n131\t\n132\t---\n133\t\n134\t## 4.

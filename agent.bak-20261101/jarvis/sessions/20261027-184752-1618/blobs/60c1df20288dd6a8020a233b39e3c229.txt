Tailwind v4 emits both `backdrop-filter` and `-webkit-backdrop-filter` automatically; `bg-*` opacity compiles to `color-mix()`.\n14\t- **Compatibility with Antigravity UI + Tailwind CSS 4:** Antigravity UI is a Tailwind-based component system (utility-first, no hard-coded opaque fills), so glass utilities compose directly on its components. Tailwind v4's `supports-[backdrop-filter]:` variant provides solid-fill fallbacks for browsers without `backdrop-filter`; avoid nesting glass inside glass (inner panel can only blur the outer panel's contents).\n15\t- **Accessibility:** check contrast over the *effective* surface color (not just the fill) — a 60% white fill over violet can yield ~4.0:1, failing 4.5:1 for body text; use darker text or raise opacity. Support `prefers-reduced-transparency` (custom Tailwind variant) and `prefers-contrast: more` (`contrast-more:` variant); add `scroll-padding-top` for sticky glass headers so focused elements stay visible; never animate `backdrop-filter` radius itself.\n16\t- **Performance:** `backdrop-filter` recomputes whenever content behind the panel changes (scrolling under sticky headers). One header/card is fine; many glass panels, very large panels, or animating blur radius cause jank on low-end phones. Reduce glass surface count before reducing blur radius; avoid `backdrop-filter`/`opacity` on `<body>` or page wrappers (blocks child blur).\n17\t- **Recommended stack:** Tailwind CSS 4 (native `backdrop-blur-*`, `supports-[backdrop-filter]:`, `color-mix()` opacity) + Antigravity UI components + custom `glass` design tokens in `tailwind.config.js`/CSS variables + React 19 components with `prefers-reduced-transparency`/`prefers-reduced-motion` guards + optional `@yhooi2/shadcn-glass-ui` for pre-built glass primitives.\n18\t\n19\t---\n20\t\n21\t## Glassmorphism CSS Techniques\n22\t\n23\t### Core glass surface recipe (Tailwind v4)\n24\t\n25\t```tsx\n26\t<div className=\"rounded-2xl border border-white/20 bg-white/60 p-6 shadow-lg backdrop-blur-lg backdrop-saturate-150\">\n27\t  {/* content */}\n28\t</div>\n29\t```\n30\t\n31\t| Part | Utility | Purpose |\n32\t|------|---------|---------|\n33\t| Translucent fill | `bg-white/60` (or `bg-slate-900/60`) | Lets background show through; opacity drives readability |\n34\t| Backdrop blur | `backdrop-blur-lg` (16px) / arbitrary `backdrop-blur-[20px]` | Frosted effect; Tailwind v4 scale xs→3xl |\n35\t| Saturation boost | `backdrop-saturate-150` | Offsets gray cast from light fills |\n36\t| Edge | `border border-white/20` | Separates panel where blur alone doesn't |\n37\t| Shadow | `shadow-lg` | Depth separation |\n38\t\n39\t### Fallback for browsers without `backdrop-filter`\n40\t\n41\t```tsx\n42\t<div className=\"rounded-2xl border border-white/20 bg-white/95 p-6\n43\t  supports-[backdrop-filter]:bg-white/60 supports-[backdrop-filter]:backdrop-blur-lg\">\n44\t  {/* content */}\n45\t</div>\n46\t```\n47\t\n48\tSolid fill first; translucency only where `backdrop-filter` is supported. Tailwind v4's `supports-[backdrop-filter]:` variant generates the `@supports` block automatically.\n49\t\n50\t### Sticky glass header\n51\t\n52\t```tsx\n53\t<header className=\"sticky top-0 z-40 border-b border-slate-900/10 bg-white/95\n54\t  supports-[backdrop-filter]:bg-white/75 supports-[backdrop-filter]:backdrop-blur-md\">\n55\t  {/* nav */}\n56\t</header>\n57\t```\n58\t\n59\tKeep fill high (75%+) since header text sits over whatever scrolls past. avoid full-page backgrounds and nesting glass inside glass.\n80\t4. **Contrast-test over real backdrops** — check text contrast over the effective surface color across light/dark and image backdrops; adjust fill opacity or text color.\n81\t5. **Add accessibility variants** — `reduce-transparency:bg-white reduce-transparency:backdrop-blur-none`, `contrast-more:` for higher contrast.\n82\t6. **Performance guardrails** — limit concurrent glass surfaces, avoid animating blur radius, don't put `backdrop-filter`/`opacity` on `<body>` or wrappers.\n83\t\n84\t---\n85\t\n86\t## Compatibility Notes: Antigravity UI + Tailwind CSS 4\n87\t\n88\t- **Antigravity UI** is a Tailwind-first component system; its components accept `className` overrides, so `backdrop-blur-*`, `bg-*/opacity`, and `border-*/opacity` utilities compose directly without fighting component styles.\n89\t- **Tailwind CSS 4** compiles `bg-white/60` to `color-mix()` and emits both `backdrop-filter` and `-webkit-backdrop-filter` for every `backdrop-*` utility — no manual vendor prefixes needed.\n90\t- **`supports-[backdrop-filter]:`** variant provides progressive enhancement: solid fill on unsupported browsers, glass on supported ones.\n91\t- **Avoid nesting glass inside glass** — the inner panel can only blur the outer panel's contents, not the page behind.\n92\t- **Don't apply `opacity`/`filter`/`backdrop-filter` on `<body>` or page wrappers** — these create a backdrop root that blocks child panels from blurring page content.\n93\t\n94\t---\n95\t\n96\t## Accessibility Considerations\n97\t\n98\t- **Contrast:** verify text contrast against the *effective* surface color (fill blended with backdrop), not the fill alone. A 60% white fill over violet can measure ~4.0:1 (fails 4.5:1 body minimum); use darker text or raise opacity to 75–80%.\n99\t- **`prefers-reduced-transparency`:** add a custom Tailwind variant (`@custom-variant reduce-transparency (@media (prefers-reduced-transparency: reduce))`) and switch to solid fill + `backdrop-blur-none`.\n100\t- **`prefers-contrast: more`:** use Tailwind's `contrast-more:` variant to increase fill opacity / border contrast.\n101\t- **`prefers-reduced-motion`:** disable backdrop animations; don't animate `backdrop-filter` radius.\n102\t- **Sticky headers:** add `scroll-padding-top` to `html` so focused elements don't hide behind the glass header.\n103\t- **Focus indicators:** ensure focus-visible rings remain visible over translucent surfaces.\n104\t\n105\t---\n106\t\n107\t## Performance Implications\n108\t\n109\t- `backdrop-filter` recomputes whenever content behind the panel changes (e.g., page scrolling under a sticky header).\n110\t- One header or card is normally fine; problems appear with many glass panels on screen, very large panels, or animating blur radius.\n111\t- On low-end phones, reduce the number of glass surfaces before reducing blur radius.\n112\t- Never apply `backdrop-filter` or `opacity` to `<body>` or page wrappers — it blocks child blur and forces full-page recompositing.\n113\t\n114\t---\n115\t\n116\t## Sources\n117\t\n118\t- GradientDeck, \"Glassmorphism in Tailwind CSS v4: blur, fallbacks, and readable text\" — https://gradientdeck.com/blog/glassmorphism-in-tailwind-css-v4\n119\t- OpenReplay, \"Creating Blurred Backgrounds Using CSS Backdrop-Filter\" — https://blog.openreplay.com/creating-blurred-backgrounds-css-backdrop-filter/\n120\t- UXPilot, \"12 Glassmorphism UI Features, Best Practices, and Examples\" — https://uxpilot.ai/blogs/glassmorphism-ui\n121\t- Antigravity UI Skill (UI Styling) — https://www.antigravityskills.org/skill/ui-styling\n122\t- @yhooi2/shadcn-glass-ui (npm) — https://www.npmjs.com/package/@yhooi2/shadcn-glass-ui"}
